Every package manager on your machine, one command.

repoke finds Homebrew, npm, pnpm, pip, cargo, apt, winget and the rest of what you have installed, shows what is outdated and upgrades what you pick. In a terminal it asks first. In scripts, cron jobs and AI agents it runs without asking and answers in JSON.

Install

brew tap paveldelpozo/tap && brew trust paveldelpozo/tap
brew install repoke

or with Rust

cargo install repoke

Or download the binary for macOS, Linux or Windows from the releases. repoke self-update keeps it current.

System

Homebrew, Mac App Store, APT, DNF, pacman, zypper, Snap, Flatpak, WinGet, Scoop, Chocolatey

Languages and tools

npm and pnpm globals, Node through fnm or nvm, pip, uv, cargo, rustup, RubyGems, Composer, mise

The last two lines above are plugins, which is how anything else gets in.

Check first, upgrade what you choose

repoke check                    # what is outdated; nothing changes
repoke upgrade                  # pick from a list, everything preselected
repoke upgrade --dry-run        # the commands it would run
repoke upgrade --hold eslint    # leave a package where it is

Each package gets a line with its result and how long it took, and a failure shows the command with the end of its output. Managers run side by side while checking and one after another while upgrading. npm installs the exact version it listed, so a newer release can't break the Node you have. Node versions under fnm or nvm move to the newest release of their major line and take your global packages with them.

A new machine, and updates while you sleep

repoke export                 # what you installed, and your config files if you want
repoke init --from snapshot   # on the new machine, only what is missing
repoke init                   # or pick tools from a catalog
repoke schedule install       # every day at 03:00

Values that look like secrets, such as registry tokens in .npmrc, are taken out before a snapshot is saved, and a restore never replaces one of your files without asking first and keeping yours as a backup. The schedule goes through the system's own scheduler: launchd on macOS, a systemd timer on Linux, Task Scheduler on Windows.

For scripts and agents

repoke check --json                     # exits 100 when something is outdated
repoke upgrade --yes --no-sudo --json   # one JSON event per line
repoke mcp                              # MCP server over stdio

Without a terminal, repoke never waits for input: a manager that wants a password is skipped or fails at once. The MCP server gives agents check_updates and upgrade, and upgrade only previews until it is told otherwise. In Claude Code:

/plugin install repoke --marketplace paveldelpozo/repoke

Any other manager can be added with a TOML file or a small executable. repoke plugin search lists the official ones, and the plugin guide explains how to write your own.
